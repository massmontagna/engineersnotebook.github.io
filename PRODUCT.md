# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack
Delegated. The user wants a static site hosted on GitHub Pages and was unsure of the tooling. Default: plain static HTML/CSS/JS with no build step, which deploys directly to GitHub Pages and suits self-contained interactive demos. Revisit if content volume makes a static site generator worthwhile.

## Users
Engineering students, practising engineers, and hobbyists. They arrive to understand a concept by playing with it, or to grab a specific formula quickly. Engineers who only need a formula must not have to read through theory to find it.

## Product Purpose
Engineer's Notebook is a go-to reference for engineering theory, formulae and demos. Each formula or demo is an interactive element a reader can manipulate. Success: a reader gets the formula they came for in seconds, or builds intuition for it by interacting with a demo.

## Positioning
Demo-led: interactive demonstrations are the core of the product, with the fundamental theory and formulae kept obvious and easy to reach alongside each one.

## Operating Context
Static site served from GitHub Pages (`engineersnotebook.github.io`). Readers range from quick look-ups mid-task to longer study sessions.

## Capabilities and Constraints
- Each formula or demo has interactive elements.
- The fundamental theory and formulae for each topic must be visible without digging.
- Static hosting only: no server-side code.
- Undecided: which engineering disciplines and topics are covered at launch, and how content is organised.

## Evidence on Hand
Only a one-line README ("Your go-to for engineering theory, formulae and demos."). No content, demos, branding or assets exist yet. Future work must not fabricate authors, credentials, usage figures or testimonials.

## Product Principles
- Demos lead, but the formula is never buried behind them.
- Quick lookup and deeper learning are both first-class paths through the same page.
- Every formula or demo is interactive where interaction helps understanding.
- Stay static and dependency-light so the site is simple to host and maintain.
